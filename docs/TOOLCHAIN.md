# Vite build/dev and static hosting contract

Use Node 22.12+ on the Node 22 line, or Node 24+. CI continues using Node 22. Run `npm ci`, `npm start` (or `npm run dev`) and open `http://localhost:3000`. The server binds only to loopback and fails if port 3000 is occupied, preserving the backend's exact-origin default rather than silently choosing another port.

The original public `REACT_APP_API_URL` setting is retained in `.env.local` or the build environment. Its default remains `/notepad`. This is public configuration, never a credential. Vite loads and defines only that exact setting; automatic `VITE_*` exposure is disabled. Vite supplies defined globals through its client bootstrap during development and statically replaces them in production. Restart/rebuild after changing configuration. Root-relative public images and CSS keep their original URLs; the JSX entrypoint is now `src/index.jsx` and root `index.html`.

`npm run build` still writes `build/`; the generated JS files now live under `build/assets/`. Do not assume CRA's former `static/js` paths in downstream scripts. `npm run preview` serves the existing build locally on port 3000; it is a verification server, not production hosting. Vite's modern production browser target replaces CRA's Browserslist-driven compilation; legacy-browser parity is not claimed. Desktop/mobile visual and cookie checks remain a release gate.

The public `_redirects` file declares Netlify's SPA fallback (`/* /index.html 200`) for direct `/auth` and `/notes` navigation. A same-origin `/notepad` API proxy rule must come **before** this fallback in approved host configuration. Otherwise API requests can receive HTML. Other static hosts need their equivalent rewrite, with assets served normally and API routes excluded. No hosting configuration or deployment was performed; local preview fallback does not establish hosted behavior.

Checks: `npm run lint`, `npm test -- --watchAll=false --runInBand`, `npm run build`, then `npm run test:toolchain`. All 18 existing Jest behavior tests remain: 14 mocked UI/context checks and four actual Axios Node HTTP requests to a disposable synthetic server. Seven additional integration cases exercise the shared production route table with the actual Router 7, AuthProvider and screens; API responses and toast notifications are mocked. The jsdom test environment uses Node Web Request/abort implementations together. The toolchain script compiles a synthetic API override in memory, verifies private-setting exclusion and Vite's actual dev bootstrap/JSX, compares copied public assets byte-for-byte, and requests root/auth/notes from dev and preview servers. It uses no browser, live API, database, provider or existing secrets. Plain JavaScript has no typecheck command. Existing ordinary CI includes this check; daily engineering triggers are unchanged.

Current dependency limits: full audit has 19 moderate findings; runtime-only has zero findings after the pinned Router 7.18.4 upgrade. No high/critical findings. ESLint 9 is deprecated/unsupported but retained because the current React lint plugin declares support through 9; upgrading ESLint 10 with forced peers is not accepted. Jest's YAML/formatting chain and glob/encoding deprecation warnings remain. Audit findings are not automatically evidence of exploitation in the shipped bundle. Review the remaining tool-only paths independently; do not force unsupported peer versions.

Rollback: restore the previous frontend revision and locked install/build commands if supported CI or actual browser/host checks regress. API endpoints, Origin/header boundary, cookie behavior, embedded notes and deployment order are unchanged. Keep the paired auth release coordinated; ship backend duplicate-key handling before an owner-approved audited/backed-up paused-registration username index build. No data or infrastructure rollback is required for this toolchain slice.
